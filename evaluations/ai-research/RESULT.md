# AI 科研测试结果：通过绝对门禁，但尚未证明相对优势

这次评测得到的是一个有价值的“先失败、再纠偏”结果：初始 Skill 候选和无 Skill 基线都通过了 15/15 机器门禁，但无 Skill 基线在客观预测指标和两个候选顺序的盲评中都更好。因此，初始 A/B **不支持 Skill 带来质量优势**。根据失败定位更新 Skill 后，定向回归消除了 UTF-8 乱码和模型层级错误，两边取得完全相同的机器指标；盲评按冻结规则仍为平局，而 Skill 条件消耗了更多输入 token，所以也**不支持端到端资源节省**。

## 初始 A/B：无 Skill 基线获胜

两边面对同一冻结任务。`Q` 是禁用全部本地 Skills 的基线，`R` 只启用本 Skill、禁用其他本地 Skills。两者均为 `supported`，且各通过 15/15 机器门禁。

| 条件 | 项数 / 成本 | public RMSE | public rival lift | factorial NRMSE | factorial rival lift | shadow NRMSE | boundary MAE |
|---|---:|---:|---:|---:|---:|---:|---:|
| Q：无 Skill | 5 / 7 | 0.11910300154563654 | 0.6986635668902301 | 0.11101131021753105 | 0.8246964196333646 | 0.15920193236379035 | 0.0995371202284375 |
| R：初始 Skill | 3 / 5 | 0.1332353844878441 | 0.6629079451856466 | 0.12426452796519559 | 0.8037675924896117 | 0.18627957344997798 | 0.10054971832765626 |

Q 在所有预先报告的预测比较上都优于 R。R 的模型项更少、DSL 成本更低，但它遗漏了 `gain` 和 `delay` 原始主效应，同时又声称阈值项提供“超越加性效应”的解释。自动生成的 rival 补入了这两个主效应，使比较不再嵌套；因此，较低模型成本不是公平机制比较下的效率胜利。

双顺序盲评也定位到同一问题：

| 顺序 | Q 分数 | R 分数 | 偏好 |
|---|---:|---:|---|
| forward：Q 在前 | 100 | 66 | Q |
| reverse：R 在前 | 100 | 74 | Q |
| 均值 | **100** | **70** | **Q 胜，均差 30** |

R 的跨顺序变化恰为 8 分，冻结规则只在“超过 8 分”时标记位置敏感，所以本轮不是 position-sensitive。

端到端生成资源没有下降：

| 条件 | input tokens | cached input | output | reasoning output |
|---|---:|---:|---:|---:|
| Q：无 Skill | 307,419 | 285,824 | 6,993 | 848 |
| R：初始 Skill | 561,871 | 515,328 | 7,806 | 1,054 |

R 比 Q 多 254,452 个输入 token，即增加 82.770421%。模型结构成本和候选生成总成本是不同指标，不能据此宣称节省资源。

## 发现的偏差与闭环修复

初始测试同时暴露了两个可修正问题：

1. Windows PowerShell 5 在未显式指定编码时把中文 Skill 文本读成严重乱码，可能削弱了语义执行；
2. Skill 当时没有明确要求“高阶增量 claim 必须保留匹配的低阶主效应”，导致主模型和 rival 层级不一致。

定向回归所使用的修订版本增加了 PowerShell 5 UTF-8 可移植性指令，以及科研“结构层级门”。提交 [`3278710dc8a141a5ecb9a7651c86ea2b9da631e6`](https://github.com/sjysjysjy728/comprehensive-engineering-cybernetics-skill/tree/3278710dc8a141a5ecb9a7651c86ea2b9da631e6) 是评测后发布的字节一致快照，不是对评测当时 runtime HEAD 的同时代绑定；其中两个被评测文件的哈希为：

- `SKILL.md`: `14b6fd6a1e831baf92853bb6f9e9c1fa1b473bc2f1343548522daf9350100fb0`
- `references/ai-research.md`: `138c0a49eedfa9159e669e4067360ccaa544eee32a20c77b596ec6012b942e8c`

这些改动来自已经观察到的初测失败；后续实验因此是 benchmark-informed 的定向回归，不是新的独立验证。后续发布可以继续修改 Skill，但不能把该历史 A/B 的结果绑定到新文件或解释为新版本证据。

## 修复后定向回归：机器指标相同，盲评平局

回归改用中性路径标签：`Q` 为无 Skill，`R` 为修订后的 Skill。两边都产生了包含 `gain`、`delay`、`load`、`ambient` 主效应及 `hinge_product(gain, delay)` 机制项的 5 项、成本 7 模型，均通过 15/15 门禁。机器指标完全相同：

| 指标 | Q | R |
|---|---:|---:|
| public RMSE | 0.11910300154563654 | 0.11910300154563654 |
| public rival lift | 0.6986635668902301 | 0.6986635668902301 |
| factorial NRMSE | 0.10329295109679625 | 0.10329295109679625 |
| factorial rival lift | 0.8356169973096652 | 0.8356169973096652 |
| shadow NRMSE | 0.12891219125043282 | 0.12891219125043282 |
| boundary MAE | 0.09775127909609374 | 0.09775127909609374 |

有效双顺序盲评为：

| 顺序 | Q 分数 | R 分数 | 偏好 |
|---|---:|---:|---|
| forward：Q 在前 | 96 | 96 | tie |
| reverse：R 在前 | 95 | 100 | R |
| 均值 | 95.5 | 98.0 | **冻结规则为 tie** |

虽然 R 均分高 2.5 分，但 forward 是平局、reverse 才偏好 R，偏好不一致；冻结规则要求两个顺序都偏好同一候选且均差至少 5，因此结果是 tie。Q 和 R 的跨顺序变化分别为 1 和 4，未触发位置敏感。

forward 的第一次判决没有进入聚合：判官自报第一候选总分为 83，但按 30/25/20/15/10 权重从维度分重算为 82；第二候选自报和重算均为 94。聚合器 fail closed 丢弃整份判决并在新上下文重跑，上表只使用有效重跑结果。

回归仍没有显示资源节省：

| 条件 | input tokens | cached input | output | reasoning output |
|---|---:|---:|---:|---:|
| Q：无 Skill | 353,634 | 329,472 | 9,259 | 1,079 |
| R：修订 Skill | 552,310 | 510,848 | 7,800 | 1,056 |

R 比 Q 多 198,676 个输入 token，即增加 56.181250%。R 的 output 和 reasoning output 较少，不能抵消已记录的输入 token 增幅，也不足以支持总体成本更低。

## 能力结论与证据边界

本测试支持三件事：候选能在受限 DSL 和证据上限内形成可运行的科研假设；测试能发现 claim-to-code 不保真的结构错误；Skill 能把具体失败转化成可机械检查的运行时和结构门禁，并在定向回归中消除已知错误。

本测试不支持以下更强结论：

- Skill 相对无 Skill 具有质量优势；
- Skill 能节省端到端 token、算力、时间或总体成本；
- 阈值项获得了因果或机制证明；
- 结果可泛化到真实数据、其他任务、其他模型或生产环境；
- 修复后结果构成独立确认。

证据只来自一个合成任务和单一生成器，结论上限是测试范围内的预测关联。候选和盲评判官来自同一 Codex 模型家族；没有系统调用级隔离证明，也没有对全部运行资源做取证级匹配。held-out 结果发布后已不再隐藏，初始 A/B 与事后定向回归不能合并为因果效应估计。

## 公开审计

`submission.json` 是修复后 R 候选的可审计示例，SHA-256 为 `51ca953d0eee5390b35657a9538a67853fe5bc797909e3d356c302208ceece0e`。在本目录运行：

```bash
python -I -B evaluate.py --check result.json
```

预期输出以 `PASS: PUBLIC-AUDIT` 开头。审计器严格解析 JSON，并检查提交哈希、三个 Idea Card、模型成本、主效应嵌套、15/15 记录、关键精确指标、token 算术、盲评聚合和裁决。它只做公开回归审计，不重新运行模型、冻结解释器或历史隐藏数据。
