# 公开评测

这里公开三个互补的合成评测，用来检验本 Skill 在项目交付、AI 科研和受限资源组合三类任务中的行为。每个目录都包含任务、评分规则、候选产物和可复算结果；统一入口只使用 Python 标准库，并以子进程退出码作为机器门禁。

| 评测 | 公开结果 | 能支持的结论 | 不能支持的结论 |
| --- | --- | --- | --- |
| [项目交付](project-delivery/TASK.md) | 缺陷程序历史起点通过 8/52 项检查；显式调用 Skill 的运行修正后通过 52/52，历史独立量表为 100/100 | 在该固定任务上，需求分解、反例驱动修正和最终验收形成了完整闭环 | 没有匹配的“无 Skill 写作”对照；公开包不能重建 8/52 起点或重算过程分 |
| [AI 科研](ai-research/TASK.md) | 初始 A/B 中两方都通过 15/15 机器门禁，但 Skill 候选盲评均分为 70，对照为 100；修正结构层级规则后的定向回归中，Q/R 机器指标相同，盲评均分 95.5/98.0，但因顺序偏好不一致按冻结规则判平局 | 初始负结果能暴露 claim-to-model 不一致；定向回归确认这个固定错误已闭合 | 定向回归受已知失败启发，不是新的独立验证或 Skill 优势证明；也未节省端到端 token |
| [资源组合](resource-synthesis/TASK.md) | `GAIN-VERIFIED`：三种非顶级资源按角色组合后的 exact 为 0.80，同预算单资源为 0.35–0.40，成本为 3、深度为 1 | 在该确定性结构任务上，专长分工、来源追踪和共同故障保护产生了可复算增益 | 没有“无 Skill 写作”对照；固定均衡错误桶不是分布泛化，不能外推到真实资源 |

详细证据和限制分别见各目录的 `RESULT.md` 与 `result.json`。AI 修复后的回归只用于确认已识别缺陷是否被纠正；其盲评按预声明规则也是平局，不能被解释为新的比较优势。

## 一键复现

在仓库根目录运行：

```bash
python -X utf8 -I -B evaluations/run_all.py
```

`run_all.py` 根据自身文件位置解析三个评测目录，因此其行为不依赖启动时的当前工作目录。它依次执行：

```text
project-delivery/acceptance_test.py counter_merge.py
resource-synthesis/evaluate.py --check result.json
ai-research/evaluate.py --check result.json
```

所有子进程输出都会被捕获。最后一行输出是一个 JSON 对象，包含每项评测的状态、退出码、标准输出和标准错误；任一评测退出码非零时，总命令也以非零状态退出。

也可以进入对应目录，使用上述参数单独运行某一项。推荐保留 `-I -B`：前者隔离用户级 Python 环境，后者避免生成字节码缓存。

## 证据边界

- 这些都是单个合成任务，不代表真实项目、真实科研数据或其他资源组合上的平均效果，不能据此外推生产能力。
- 任务、结果和可复算夹具公开后都已失去盲测资格；资源组合包使用另行派生的公开回归夹具，原始 held-out seed/reveal 未发布。当前命令只能做确定性回归或公开审计，不能重建历史 held-out 条件。
- 三类评测的任务、量表和成本口径不同，分数不能跨评测直接比较。
- 只有 AI 初始实验包含匹配的 Skill/无 Skill A/B；项目交付与资源组合结果都缺少匹配的无 Skill 写作基线。
- 自动门禁证明的是公开条件下的可复算结果，不等同于因果归因、现实有效性、长期稳定性或人工复核。
