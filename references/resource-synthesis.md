# 资源综合与结构增益

当结果依赖多个能力有限的现有代码、模型、数据、工具、服务、人员或 Agent 时使用本文件。设计对象是组合后的系统，不是把每个部件都升级成“顶级资源”。目标是：

```text
在全部硬约束和资源包络内，
让每项资源只承担经验证能够胜任的角色，
通过互补、校验、隔离、路由和反馈，使整体优于同条件下与声明相关的最佳获准单体。
```

“更好”必须指向冻结的目标向量：可以是同预算下质量、可靠性或覆盖率更高，也可以是同等质量下成本、延迟或资源更低。它不意味着在所有维度击败无限预算的前沿资源。

若一个现有资源已经能以更低全生命周期成本满足全部硬要求，直接采用并验证；不要为了形式上的协同增加组件。

## 1. 冻结系统增益的比较契约

组合前先固定：

| 字段 | 内容 |
|---|---|
| Target vector | 必须逐项满足的硬指标、允许优化的指标及守护指标 |
| Single-resource baselines | 当前权限、预算和环境中所有可运行的相关单体；每个声明方向对照满足相同守护条件的最佳者，无唯一最佳时保留非支配单体集合 |
| Matched conditions | 相同任务/数据、工具权限、时间窗口、总推理/训练预算、总调参机会、延迟包络、资源核算和评价协议 |
| Minimum gain | 足以改变采用决定的最小增益及测量不确定性 |
| Composition budget | 路由、通信、验证、重试、存储、维护和故障恢复的总开销上限 |
| Claim boundary | 声明是质量增益、可靠性增益、成本节约，还是这些维度的明确 Pareto 改善 |

若基线、条件或“更好”的含义未固定，只能把组合当候选架构，不能声明结构增益。

用户、合同或论文 claim 明确点名的 comparator 始终保留；单体基线集合是额外的结构增益对照，不能替换指定对象。多目标下在看结果前预选比较关系：按每个声明方向对照相应条件最优单体、证明组合扩展 Pareto 前沿，或支配指定的一个/全部非支配点；不得在结果出来后挑选最容易胜出的关系。

跨平台成本比较同时保留物理用量和货币估值，不把不同口径直接相除。本地计算记录设备型号、总设备时、利用率和选定估值方法（如同期租赁价，或披露的折旧、能耗与运维口径）；API 记录输入、输出、缓存 token、工具费、重试和失败调用；另列存储、网络、人工裁决及协调时间。成本倍数必须给出价格日期、假设和敏感性，不能只比较显卡时与 API 账单中的一个局部数字。

## 2. 按角色标定资源，而不是按名气排名

在代表性任务切片上建立资源画像：

| 字段 | 要回答的问题 |
|---|---|
| Resource ID / version | 使用的究竟是哪一版代码、模型、数据、工具或人员能力？ |
| Role competence | 它在哪个窄角色中能够可靠完成什么？适用边界是什么？ |
| Evidence | 能力是本次实测、可核对来源、他方报告、估算还是未知？ |
| Cost and capacity | 单次与累计时间、金额、算力、token、并发、吞吐和上下文上限 |
| Failure signature | 常见错误、最坏切片、退化信号和无法处理的输入 |
| Dependency lineage | 与其他资源共享哪些模型、训练数据、提供商、索引、代码、基础设施或上下文？ |
| Observability/control | 能否检测其错误、限制行为、拒绝输出、替换或回退？ |
| Lifecycle | 许可、安全、隐私、维护者、升级、锁定和退出成本 |

资源只需证明其角色能力；组合系统负责证明完整目标。GitHub stars、模型规模、品牌、排行榜或 Agent 自信度只用于发现候选，不能替代角色证据。

涉及人员时，只记录经同意且已授权的职责、可用时间、专业边界和升级责任，不把人当作可任意操纵、替换或按单一分数排名的部件；劳动、安全、隐私与最终专业判断仍是治理边界。

## 3. 通过互补性与共同失效门禁

只有资源带来以下至少一种新增贡献时才值得组合：新的信息源、不同的错误机制、专门能力、可独立检查的证据、更便宜的前级筛选、故障隔离或可用备份。

组合前逐项检查：

- **角色可胜任**：每个资源在拟分配角色上有足够证据；
- **能力或信息互补**：组合填补了单体缺口，而不是复制相同输出；
- **错误可区分**：存在测试、规则、异源证据或有能力的裁决者判断分歧；
- **故障可隔离**：局部错误不会无条件污染共同输出，并且能够拒绝、切断、替换或降入安全状态；
- **切换来得及**：检测、重试和升级延迟仍满足任务窗口；
- **净收益可行**：预期增益值得支付协调、验证、延迟、维护和新增攻击面的成本。

相同模型的多次调用、相同训练/检索来源的不同包装、共享单点 API 或使用同一个有偏评价器，通常具有共同失效。除非实测证明错误足够不相关，不把它们计作独立冗余。多数投票不能消除共同幻觉；多个错误答案达成一致仍是错误。

## 4. 选择最浅的有效组合结构

| 结构 | 适用条件 | 关键控制 |
|---|---|---|
| 单体 + 守护 | 单体已覆盖主任务，错误可机械发现 | 在输出边界放确定性校验和拒绝路径 |
| 串行专业化 | 任务可分解，资源各自擅长不同阶段 | 固定接口、数据契约和端到端追踪 |
| 级联路由 | 便宜资源能处理大多数样本，难例可识别 | 预先冻结升级信号、容量和最坏延迟 |
| 并行异构 + 仲裁 | 候选错误机制有差异，仲裁有独立证据 | 不用同源多数票代替事实核验 |
| 主用 + 异源备份 | 可用性关键，局部故障可检测和隔离 | 演练故障发现、状态转移和恢复 |
| 反馈式自适应 | 结果可连续观测，动作可纠偏 | 限制增益、重试与漂移，版本化策略变化 |

优先选择能关闭当前关键误差的最浅结构。增加 Agent、模型或工具必须说明新增了什么能力、信息或故障多样性；否则先删除。允许把强资源或人工设为稀疏升级路径，但必须记录调用占比与成本；若 claim 明确要求“只依赖现有非前沿资源”，则这种隐藏后备会使 claim 失效。

## 5. 建立最小组合卡

复杂组合只维护一张 `System Composition Card`：

| 字段 | 内容 |
|---|---|
| SYN ID / target | 组合编号、对应 Requirement/Claim ID 和结论层级 |
| Components and roles | 每项资源的版本、角色、输入输出和责任边界 |
| Complementarity | 各资源新增的能力、信息或不同失败模式 |
| Common-cause risks | 共享依赖、共同盲点、单点故障和污染路径 |
| Routing/fusion | 何时调用、接受、拒绝、合并、升级或交给人工 |
| Isolation/fallback | 如何发现并隔离失败，安全状态和恢复路径是什么 |
| Budget | 正常、最坏和累计的成本、延迟、算力及维护开销 |
| Comparison | 指定 comparator、冻结的单体基线集合、比较/支配关系、匹配条件、最小增益和评价协议 |
| Next gate | 哪个最小测试决定采用、重设计、升级或停止 |

这张卡是现有项目追踪或科研 claim 链的一个节点，不另建平行事实体系。

## 6. 用系统级证据验证增益

按风险选择以下验证，不以“组件都能运行”代替整体效果：

1. **角色测试**：验证每项资源在规定输入域内胜任角色，以及超出能力时能拒绝或升级；
2. **端到端测试**：在真实接口、代表数据和规定负载下测完整目标向量；
3. **匹配对照**：按预声明关系比较指定 comparator、相关最佳获准单体或非支配基线集合与组合系统，核算所有隐藏调用和协调成本；
4. **消融与替换**：移除/替换组件，确认增益来自所声称的互补机制，而不是泄漏、额外预算或单个强后备；
5. **错误重叠**：报告共同错误、分歧、最坏切片和错误相关性，而不只报平均分；
6. **故障注入**：只在明确获准的非生产环境或隔离演练中，以有限影响范围和可回退方案验证超时、错误输出、依赖中断、仲裁失败、隔离、切换和恢复；不能安全注入时使用模拟故障或故障替身，并标明证据等级。

对组合本身给出独立裁决：

- `GAIN-VERIFIED`：组合相对冻结基线满足预声明的比较/支配关系，增益超过测量不确定性，全部硬/守护指标通过，且总开销在包络内；
- `NO-GAIN`：有效证据显示增益不足、守护指标恶化或协调成本抵消收益；
- `UNKNOWN`：基线、测量、样本、失效覆盖或成本证据不足。

`GAIN-VERIFIED` 只证明该比较契约内存在系统增益，不自动等于项目 `PASS`、科研 `supported-at-F4` 或生产可用。

## 7. 运行中的升级、学习与停止

记录路由选择、分歧、拒绝、升级、人工接管、失败切片、成本和最终结果，用实际误差更新角色边界与路由阈值。会影响验收或论文结果的在线策略变化必须版本化并重新验证，不能边看结果边无记录地修改。

出现以下情况时升级关键资源、重建结构或停止增加组件：

- 所有资源在关键切片上共同失败，且没有独立观测或新信息源；
- 路由器/仲裁器不能可靠区分正确与错误，或本身成为未受控单点；
- 新组件没有降低关键误差或增加有效覆盖，只增加通信、延迟和维护；
- 故障无法隔离、切换晚于任务窗口，或共同依赖突破安全边界；
- 组合仍不可达到硬目标，或边际增益低于测量噪声和全生命周期成本。

停止时保留单体与组合证据，准确报告缺失的能力、信息或控制权。不得用“已调用多个资源”作为完成证明。

## 两个应用域的典型映射

- **项目交付**：用现有模块/平台承担窄功能，适配器固定接口，确定性测试器守住合同项，便宜路径处理常规流量，异源备份或有权限的人工处理故障；最终仍在合同环境中验收整个系统。
- **AI 科研**：用低成本模型或小实验发散和筛选，用检索提供可核对近邻，用程序测试 Core，用异构评价和高保真度实验确认；若研究贡献本身是组合机制，必须用匹配单体、消融、共同错误和开销证明结构增益。
