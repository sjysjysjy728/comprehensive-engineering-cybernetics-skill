# 项目交付模式：公开评测结果

## 结论

在 2026-09-03 冻结的这一项小型、确定性 Python 修复任务上：

| 阶段 | 结果 | 证据性质 |
|---|---:|---|
| 缺陷起始程序资格检查 | `8/52` | 冻结前实测；起始文件 SHA-256 已记录 |
| Skill 驱动后的首次完整验收 | `52/52` | 实测，退出码 `0` |
| 主流程退出后的独立复跑 | `52/52` | 实测，退出码 `0` |
| 历史独立无 Skill 评分 | 产品 `90/90`、过程 `10/10`、总分 `100/100` | 当次源码审阅、冻结量表与独立复跑；过程原始轨迹未公开 |

在这一次显式调用该 Skill 的运行中，代理把已有但严重不合格的程序组织成满足全部冻结指标的交付物，并保留了验收证据。这个历史结果绑定测试时的源码提交 `7fa3bb8df271183c7aaf7d0c04a10510614f1f94`，不会自动外推到当前版本。它不证明对所有项目都有效，也没有提供“同一个代理、不使用 Skill”的匹配修复对照，因此不能把全部改善严格归因于 Skill。

## 复现当前交付物

本目录不需要第三方依赖：

```bash
python -I -B acceptance_test.py counter_merge.py
```

预期返回码为 `0`，最后一行 JSON 中 `checks=52`、`passed=52`、`failed=0`。`duration_seconds` 会随机器变化。公开的 `counter_merge.py` 是当次受测最终文件；其 SHA-256 为 `f8dc771c7dce05eb9e1089514329afa4dcbc6203e2f0036e5aa86168e959058d`。

缺陷起始文件只记录了 SHA-256 `e24a24ef1dc51dc3b659754bb31a340b0357dd5c7d238ba80a0c5fcf59dc1b12`、209 字节和 `8/52` 资格结果，没有包含在公开包中。因此当前包可以复现最终产品的 `52/52` 回归，但不能单独重建历史起点，也不能重算依赖当次执行过程的 `10/10` 过程分。冻结任务、量表和实际运行提示分别见 [TASK.md](TASK.md)、[RUBRIC.md](RUBRIC.md) 与 [RUN_PROMPT.md](RUN_PROMPT.md)。

## 观察到的闭环行为

历史目标会话明确进入项目交付模式，只读取目标 Skill 的 `SKILL.md` 和 `references/project-delivery.md`。它先测得 `8/52` 基线，将失败聚类为协议、解析分类、模式验证、合并逻辑和确定性输出，再只修改目标文件；没有降低阈值、改验收器或删除需求。首次实际实现即通过全部 52 项门禁，最终报告还给出了需求映射、正反例和未验证边界。

冻结验收器会主动阻断被测程序写文件、联网和启动子进程，并比较输入与目标目录前后快照。任务、量表、提示和验收器在执行前以哈希冻结并设为只读；执行后哈希一致。

## 隔离与资源限制

- 行为测试使用一次性会话，忽略用户配置和规则，并把目标之外枚举到的 48 个本地 Skill 全部禁用；提示禁止网页、子代理、编辑器 Skill/提示、书籍 PDF/OCR 和任务目录外材料。观察到的轨迹没有出现这些能力的实际调用。
- 执行引擎由本机 VS Code 扩展打包，但没有观察到读取或调用扩展内相似 Skill/提示。这不是物理独立于该安装包的证明。
- 客户端启动时曾尝试预热推荐插件缓存并失败；没有安装或调用插件，所以只能声称“未观察到网络资源被用于解题”，不能声称进程从未尝试联网。
- 由于本机 `workspace-write` 错误阻断全部子进程，成功尝试使用了 `danger-full-access`。隔离依赖严格配置、只读哈希、冻结提示和命令轨迹，而非 OS 级沙箱。
- 没有完整系统调用/文件访问审计，不能做取证级证明；最终哈希一致也不能单独证明文件从未被临时修改后恢复。
- 成功会话报告输入 `410,028` tokens，其中缓存输入 `359,808`；差额为 `50,220`。另有输出 `5,278` tokens、推理输出 `869` tokens。对这样的小任务，这一成本明显偏高，是当前实现的重要缺点。

## 使用边界

任务、代码和验收器现已公开，所以本用例从此只应作为回归/烟雾测试。未来要估计泛化能力或 Skill 的因果增益，应使用未公开的新任务、匹配的无 Skill 对照、多次重复和更严格的访问审计。
