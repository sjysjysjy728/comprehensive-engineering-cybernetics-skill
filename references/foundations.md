# 理论依据与边界

## 来源范围

本 skill 编制时以钱学森、宋健《工程控制论》第三版中文版本为主要文本依据；原书、扫描件和 OCR 文本不随本仓库分发。该版本保留并扩充了 1954 年英文版的核心，但不是逐字对应的“英文原著翻译”。书中收录的修订版前言说明，第 8、12、17、20、21 章为相对 1954 年原著新增，第 9 章大部分以及其他章节的部分内容也经过增补；这些内容在第三版之前的修订过程中已形成。修订和写作是集体工作，不能把第三版每一段都表述为钱学森个人原话。

因此：

- 下表写“第三版直接依据”时，只表示能在第三版正文定位；
- 只有经版本史另行核对后，才能把具体内容称作“1954 年原著结论”；
- 项目管理、AI Agent 和 AI 科研规则均是现代操作化推演，不冒充原书原话；
- 本文件只保留短摘要和定位，不复制原书或第三方 skill 的成段文字。

## 从文本到操作规则

| 第三版直接依据 | 书中问题 | 本 skill 的现代操作化 | 边界 |
|---|---|---|---|
| 前言、第一章开头 | 理论从实践抽象并回到实践检验 | 每项设计都必须回到真实运行、测试或实验闭环 | 形式正确不等于工程有效 |
| §1.4，印刷页 8 | 工程近似只有相对具体问题和精度要求才成立 | 每个简化都写明适用条件、被忽略因素和允许误差 | 不能近似掉所研究现象的成因 |
| §1.5，印刷页 8-11 | 分析与综合；状态、受控量、控制量及其客观约束 | 先测基线和因果结构，再改造；区分目标、可观测状态和可直接操纵变量 | 不能把最终质量当成可直接设置的变量 |
| §1.6，印刷页 11-14 | 模型可由解析分解、实验测试或统计试验辨识 | 未知系统先检查结构；不可可靠分解时做小型探测或统计建模 | 模型是决策工具，不是真实本体 |
| §1.7，印刷页 14-16 | 稳定、精度、时间、超调、积分成本、抗扰和经济指标可能冲突 | 用硬约束加指标向量；逐项验收，公开 Pareto 权衡 | 不用单一综合分掩盖硬项失败 |
| §3.7，印刷页 94 起 | 输出测量经比较后回到输入，可提高准确度和响应速度 | 行动后读取真实结果，以目标偏差驱动下一步 | 仅收集日志而无纠偏权限不构成闭环 |
| §§4.10-4.11，印刷页 145-151 | 测量方案与系统共同决定能观测性；部分状态可能不可控 | 执行前检查测量能否辨错、动作能否影响目标 | “有数据”不等于能观测，“能操作”不等于能控 |
| 第 11、14、15 章 | 时滞、随机输入、噪声和估计会改变控制效果 | 明确反馈延迟、噪声、置信度和过期证据；必要时先改善信息通道 | 不把任意不确定性伪装成高斯或可线性化问题 |
| 第 13 章相关不变性讨论 | 全程保持与只锁定终端状态是不同设计问题 | 安全/合规作为过程不变量，合同验收或 claim 作为终端条件，允许路径自适应 | 不能用路径柔性突破过程硬边界 |
| 第 16 章 | 未知响应可通过有代价的探测逐步寻优，噪声与搜索损失限制探测 | 优先执行能最大幅度减少关键不确定性的有预算实验 | 盲目随机搜索在大空间中可能不可承受 |
| 第 18 章开头 | 先验不完备时通过结构或参数变化恢复可接受行为 | 反复不收敛时切换假设、模型或策略，而不是只加大同一动作 | 可达方案集中必须存在稳定/可行选项 |
| §19.1 起于 PDF p. 911；§19.2 p. 913；§19.3 p. 915 | 通过自检、隔离、重复、备份和复合结构，使局部不甚可靠的部件仍可维持系统功能 | 按角色组织有限资源，并实际验证错误检测、共同失效、fallback、切换和系统增益 | 独立失效、可检测/可切换和 k/N 功能等假设不满足时，简单堆叠可能更差；§19.4 已从 PDF p. 917 开始，冗余成本也可能不合算 |
| §21.6 起于 PDF p. 1029；§21.7 p. 1036；§21.8 p. 1039；§21.9 p. 1048 | 局部控制、信息结构、协同、多指标和资源调度可能改变全局性能 | 多模块/多 Agent 共享总目标，由协调层分配有限资源并约束局部行为；本 skill 再采用“硬项先过门、可行集合内比较 Pareto”的现代治理规则 | 第 21 章为修订版相对 1954 年原著新增，并由第三版收录；半序与不可比性不直接推出严格词典序，耦合也不保证产生增益 |

## 两个应用域的共同模型

| 控制概念 | 项目交付 | AI 科研 |
|---|---|---|
| 参考目标 | 有效合同、技术要求、验收基线 | 精确研究问题、claim 与最小有意义效应 |
| 状态 | 当前实现、依赖、缺陷、交付证据 | 当前知识、候选机制、代码与实验状态 |
| 观测 | 测试、性能测量、用户流程、验收记录 | 文献、判别实验、消融、方差和失败切片 |
| 控制动作 | 复用、实现、配置、测试、重构、回退 | 改假设、改机制、补观测、实现、实验、缩窄 claim |
| 扰动 | 需求变化、依赖故障、负载、环境和人员变化 | 噪声、随机种子、数据漂移、泄漏、近邻工作和评价偏差 |
| 约束 | 范围、指标、期限、预算、许可、安全和权限 | 诚信、核心机制、算力、时间、数据、伦理和可复现性 |
| 偏差 | 尚未满足或尚未验证的合同项 | 竞争解释仍无法区分，或 claim 与代码/证据不一致 |
| 安全状态 | 冻结范围和外部写入，保留最后验证版本 | 作废无效实验，锁定数据与日志，报告未知或停止 claim |

这些映射的用途是改善问题定义和验证，不是证明软件项目或科研过程满足某个物理控制定理。

本 skill 将上述容错与协调思想进一步操作化为 [资源综合与结构增益](resource-synthesis.md)。原书直接支持的是特定假设下的可靠性、协调和资源调度；把它扩展为模型、代码、工具、人员或 Agent 的质量/成本增益属于现代推演，必须用同条件的“与声明相关的最佳获准单体 vs 组合系统”实测，不能从原书公式直接推出。

## 现代推演的限制

- 只有在状态、动态、观测、输入、假设和判据均被正式定义时，才使用 PID、卡尔曼、李雅普诺夫或其他数学控制结论。否则用“反馈”“估计”“收敛”等普通工程语言。
- 人与组织不是被任意操纵的执行器。人的目标、同意、权限、伦理和专业判断属于系统边界与治理条件。
- 反馈可能滞后、带噪或诱发指标投机。先验证观测代表真实目标，再据此优化。
- 多 Agent 一致只增加一个意见信号，不会自动产生外部事实。
- 稳定是必要质量之一，不代表功能、性能、科学真实性或合同接受均已满足。
